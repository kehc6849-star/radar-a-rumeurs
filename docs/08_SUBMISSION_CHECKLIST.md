# 08 — Checklist de soumission

*Sources : page officielle du hackathon (hacktoberfest.galsen.dev/hackathon), page de l'événement MLH et e-mail de confirmation d'inscription. À revérifier avant la date limite : les organisateurs communiqueront d'autres informations par e-mail.*

## Dates

| Date | Étape |
|---|---|
| 7 octobre 2026 | Lancement |
| **19 octobre 2026** | **Soumission (repository, documentation, vidéo)** |
| 21 octobre 2026 | Présélection des 5 finalistes |
| **24 octobre 2026** | **Finale à Impact Hub Dakar** (page MLH : de 9 h 00 à 18 h 30, heure UTC) |

## Étapes obligatoires de participation

- [x] Inscription au challenge Open Source × AI (e-mail de confirmation reçu)
- [ ] **S'inscrire à l'événement Hacktoberfest Hack Day Dakar × Galsen DEV sur MLH** (connexion à un compte MLH ; champs demandés : prénom, nom, e-mail, téléphone, « participer au hackathon : oui », participation passée à Hacktoberfest, nom d'utilisateur GitHub)
- [ ] **Soumettre le projet dans la section Challenges de MLH** (compte MLH requis)

## Exigences open source

- [ ] Repository **public**
- [ ] **Licence open source explicite** (fichier `LICENSE` à la racine) — MIT
- [ ] **README utile**
- [ ] Documentation de l'installation et de l'utilisation
- [ ] **Historique Git visible** (commits réguliers depuis le début du hackathon)
- [ ] **Dépendances externes importantes identifiées** (voir guide de développement)
- [ ] Le projet **lui-même** est open source (utiliser seulement des dépendances open source ne suffit pas)
- [ ] Projet **initié dans le cadre du hackathon** (premier commit après le 7 octobre 2026)

## Exigences IA

- [ ] L'IA joue un **rôle pertinent et identifiable** dans la solution
- [ ] **Principaux modèles, APIs et outils IA déclarés** (voir [03 — Utilisation de l'IA](03_AI_USAGE.md))
- [ ] Aucune obligation d'entraîner son propre modèle

## Livrables

- [ ] Repository public
- [ ] README / documentation
- [ ] Description du problème et de la solution
- [ ] Explication de l'utilisation de l'IA
- [ ] Liste des modèles, APIs et outils IA utilisés
- [ ] **Vidéo de démonstration** (recommandée : 3 minutes maximum)

## Critères d'évaluation

| Critère | Poids |
|---|---|
| Pertinence du problème et utilité | 25 % |
| Pertinence de l'utilisation de l'IA | 20 % |
| Qualité technique / prototype | 20 % |
| Qualité de la démarche open source | 20 % |
| Présentation, UX et potentiel d'évolution | 15 % |

## Finale (si sélectionné)

- Pitch / démonstration : **7 minutes**
- Questions du jury : **3 minutes**
- Top 3 récompensé (les lots seront annoncés)

## Point à clarifier auprès des organisateurs

La page officielle indique « 1 à 4 personnes » par équipe dans le résumé, mais « équipes de 2 à 4 personnes » dans les conditions. Si la participation se fait seul(e), confirmer que c'est accepté (communauté Galsen DEV : links.galsen.dev).

## Script de la vidéo de démonstration (3 minutes)

1. **0:00-0:20** — Le problème : un vrai type d'arnaque que tout le monde reconnaît.
2. **0:20-1:30** — Démonstration en direct : coller un message, voir le verdict, les signaux, les conseils.
3. **1:30-2:15** — L'IA : ce qu'elle apporte que les règles ne font pas (capture d'écran, sens du message).
4. **2:15-2:45** — Open source : dépôt public, licence, comment contribuer une règle.
5. **2:45-3:00** — Vision : ce que nous ajouterons ensuite.
